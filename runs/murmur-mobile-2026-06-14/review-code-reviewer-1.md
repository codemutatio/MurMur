### What was checked and found clean

- **ADR-2 thread offload (primary concern):** The blocking `MlxWhisperTranscriber.transcribe()` call IS offloaded to the threadpool via `asyncio.get_event_loop().run_in_executor(None, lambda: ...)` (app.py:279 and 291). The `ffmpeg` decode step is also offloaded (line 279). `/health` never references the lock. The deviation from `anyio.to_thread` to `run_in_executor` is semantically equivalent and correctly flagged in implementation-notes (deviation #1). The TOCTOU issue (finding #3) is a separate concern from the offload — the offload itself is correct.
- **Validation order (§A, 11 steps):** The server's 11-step validation order matches §A exactly and is confirmed by app.py lines 185–249. The `test_server_transcribe_errors.py` suite exercises each step.
- **Constant-time compare (AC-15):** `hmac.compare_digest` is used in `token.py:64`. No timing oracle.
- **Error-code registry (ADR-8):** All 10 error codes in `app.py` match the `§A` registry exactly. `MacEngineTest` replays them verbatim via `MockWebServer`. No drift found.
- **Outbox state machine (§G, AC-31/32):** `OutboxStateMachine.transition()` enforces all valid transitions via a `Map` and enforces `done`/`failed` invariants via `require`. `NoteStatus.from()` throws `IllegalArgumentException` on unknown values.
- **Temp-file cleanup (AC-18):** `_run_transcription` wraps everything in `finally: tmp_path.unlink(missing_ok=True)`. Both success and error paths delete the temp file. Verified by dedicated tests.
- **Bearer token not in logs (AC-17):** `_TokenRedactFilter` is attached to the root logger in `create_app`. Direct token values are never passed to log calls. The test `test_token_never_logged` verifies this end-to-end.
- **KeepAlive=true in plist (AC-19):** `render_server_plist` produces `<true/>` for `KeepAlive`. `caffeinate -i` is in `ProgramArguments`.
- **OpenAI 401 → PermanentFailure (AC-40):** `OpenAITranscriptionEngine.mapResponse()` correctly maps `code == 401` to `PermanentFailure("OpenAI auth failed — check API key in Settings")`.
- **Dispatcher decision table §I:** All 11 rows tested in `DispatcherTest`. Each row maps to the correct `DispatchResult` type. `mac_401_failed_no_fallback` correctly blocks OpenAI fallback.

**Verdict: FAIL**

Blockers: 3 | Majors: 5 | Minors: 5

The single worst issue is **finding #1**: `TranscribeWorker.enqueue()` is never called from `RecordingService` or `NoteViewModel.retryNote()` in production code. The entire transcription pipeline is dead on arrival — notes accumulate as `pending` and are never dispatched. This is a complete functional failure of the core feature and is not caught by any test because the tests exercise the worker in isolation (via `TestListenableWorkerBuilder`) without testing the trigger path.

Finding #3 (TOCTOU race on the single-flight lock) is the second most serious: under concurrent load the server queues a second transcription request instead of immediately returning 503, violating the "no waiters" invariant and potentially causing the Mac to run two simultaneous transcription jobs (one blocked behind the lock indefinitely).

Finding #2 (startup stale-reset never wired) is tied for worst: any note that was `transcribing` at time of process death is permanently stuck.
